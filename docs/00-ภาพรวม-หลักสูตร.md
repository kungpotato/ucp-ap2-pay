# Workshop: ร้านขายหนังสือ Agentic Commerce (UCP → AP2 → X402 → Settlement บนบล็อกเชน)

## เป้าหมายรวมของหลักสูตร

ผู้เรียนจะสร้างระบบ "ร้านขายหนังสือ" ที่ตัวแทน AI (agent) ซื้อของแทนมนุษย์ได้จริง
ตั้งแต่การค้นสินค้า ต่อรอง/ยืนยันคำสั่งซื้อ ไปจนถึงการจ่ายเงินและ settle บนบล็อกเชนจริง
(fork จาก mainnet ด้วย Foundry) โดยเดินตามสถาปัตยกรรม 4 ชั้น:

```
UCP (Universal Commerce Protocol)   → อธิบายสินค้า/ตะกร้า/คำสั่งซื้อ เป็นภาษากลางที่ agent เข้าใจ
AP2 (Agent Payment Protocol)        → มนุษย์มอบอำนาจ (mandate) ให้ agent จ่ายเงินแทนได้อย่างปลอดภัย
X402 (HTTP 402 Payment Required)    → agent เจรจา/จ่ายเงินแบบ machine-to-machine ผ่าน HTTP 402
Settlement บนบล็อกเชน (Foundry)     → เงินเคลื่อนจริงบน EVM chain ที่ fork มาจาก mainnet
```

## สแตกเทคโนโลยี

| ส่วน | เทคโนโลยี | เหตุผล |
|---|---|---|
| Backend | Go (net/http + chi, ไม่พึ่ง framework หนัก) | เรียบง่าย อ่านง่ายสำหรับ workshop |
| Frontend | Next.js (App Router) | มาตรฐานปัจจุบัน, SSR/CSR ผสมกันได้ |
| Agent / LLM | OpenRouter (มี fallback เป็น rule-based parser) | ไม่บังคับให้ทุกคนมี API key ก็เรียนต่อได้ |
| Payment (fiat) | Stripe test mode | ใช้สาธิตขั้น AP2 mandate → checkout แบบเดิมก่อนเข้าสาย on-chain |
| Blockchain | Foundry (anvil fork mainnet) + Solidity settlement contract | ได้สภาพแวดล้อมเหมือน mainnet จริงแต่ปลอดภัย ไม่เสียเงินจริง |
| Diagram | Claude Visualize widget → export SVG | เอกสารมีภาพประกอบทุกบท |

## โครงสร้างบทเรียน

แต่ละบทมีไฟล์ `docs/NN-ชื่อบท.md` พร้อม "เป้าหมาย" และ "เรียนไปทำไม" เสมอ,
ไดอะแกรมที่จำเป็น (`docs/diagrams/NN-*.svg`) และ GIF สาธิต (`docs/gifs/NN-*.gif`)

| บท | ชื่อ | โฟกัส |
|---|---|---|
| 0 | ภาพรวมหลักสูตร (ไฟล์นี้) | ทำไมต้อง UCP→AP2→X402→settlement |
| 1 | UCP: แคตตาล็อกและตะกร้า (Go backend) | สคีมา product/cart/order ที่มนุษย์และ agent ใช้ endpoint ชุดเดียวกัน |
| 2 | UCP: หน้าร้าน Next.js | storefront จริงที่คุยกับ backend บทที่ 1 (catalog → book → cart) |
| 3 | AP2: Intent → Cart → Payment Mandate | มนุษย์มอบอำนาจจ่ายเงินให้ agent อย่างมีขอบเขตและตรวจสอบได้ (เซ็นด้วย ed25519) |
| 4 | X402: agent จ่ายเงินแบบ machine-to-machine | ใช้ HTTP 402 เป็นภาษาต่อรองราคา/จ่ายเงินระหว่าง agent กับ merchant server |
| 5 | Settlement บนบล็อกเชน (Foundry fork mainnet) | เงิน USDC จริง (จาก fork) เคลื่อนผ่านสัญญา Settlement.sol ที่ตรวจสอบ receipt จาก X402 |
| 6 | Agent self-checkout: ประกอบร่างทั้งระบบ | ปุ่มเดียวที่ agent ค้น/จ่ายเงินแทนมนุษย์ตั้งแต่ต้นจนจบบนเชนจริง |

> หมายเหตุ: หลักสูตรนี้ตั้งใจไม่ทำ "AI agent แชทภาษาธรรมชาติ" ซ้ำกับ
> workshop พี่น้อง [`ucp-ag-pay`](../../ucp-ag-pay) — ที่นี่ "agent" หมายถึง
> ตัวที่ถือ wallet และตัดสินใจจ่ายเงินจริงบนเชนแทนมนุษย์ (บทที่ 6)

## หลักการออกแบบ

1. **ทุกบทรันได้อิสระ**: โค้ดบทก่อนหน้าเป็น dependency ของบทถัดไป แต่ backend/frontend มี flag เปิด-ปิดฟีเจอร์ตามบทได้
2. **ไม่มี mock ที่ปลอมความเสี่ยงจริง**: Stripe เป็น test mode, บล็อกเชนเป็น anvil fork (เงินไม่จริง) แต่ protocol/flow เหมือนของจริงทุกขั้นตอน
3. **เอกสารเป็นภาษาไทย โค้ด/คอมเมนต์เป็นภาษาอังกฤษ** ตามธรรมเนียมทีมวิศวกรรม
4. **ทุกบทจบด้วยคำถาม "เรียนไปทำไม"** ระบุไว้ในหัวไฟล์ md ของบทนั้น ๆ
